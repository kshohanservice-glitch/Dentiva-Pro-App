# Dentiva Pro — Architecture Specification

Version: 1.0.0 · Date: 2026-09-26 · Status: Final build spec

## 1. System overview

Dentiva Pro is an **offline-first** Windows desktop application:

- **Shell:** Tauri 2 (Rust + OS webview). No Electron/Chromium bundle.
- **Frontend:** React 19 + TypeScript (Vite). Custom premium design system, no CSS framework.
- **Backend:** Rust command layer (`src-tauri`) — all persistence, auth, RBAC
  enforcement, backup/restore, attachments, activation, printing integration.
- **Database:** SQLite (single file, WAL mode, FK enforced on every connection).
- **Fallback runtime:** When the Tauri runtime is absent (browser preview / automated
  tests), `src/backend/browserBackend.ts` implements the **same command contract**
  with the **same permission checks** over sql.js (SQLite/WASM) + IndexedDB
  attachments. Frontend code never touches storage directly — it only calls the
  command API (`src/api.ts`), so authorization always lives below the UI layer.

## 2. Layering (strict)

```
React components (presentation only)
        │  typed calls, no SQL, no permission logic
src/api.ts (typed command client)
        │  invoke(cmd, args)
┌───────┴────────────────────────────────────────────┐
│ Command layer (authoritative)                      │
│  Tauri:  src-tauri/src/commands/*.rs (Argon2id,    │
│          rusqlite, filesystem, dialogs, printing)  │
│  Fallback: src/backend/browserBackend.ts (PBKDF2,  │
│          sql.js, IndexedDB) — same checks          │
│  Responsibilities: session, RBAC, validation,      │
│  transactions, audit, notifications                │
└───────┬────────────────────────────────────────────┘
        │ SQL (parameterised, transactions)
SQLite (db/schema.sql — single source of truth)
Attachments: appData/attachments/** (native) / IndexedDB (fallback)
```

Rules:

- No SQL in `src/features/**` or `src/components/**`.
- No permission branching on raw role names in UI except for *display*; every
  command re-validates the caller's permission set from the DB.
- Money: integer paisa end-to-end; formatting only at presentation (`lib/money`).
- All multi-step business operations run in a transaction (invoice+items+payment
  state+audit; payment+allocations+invoice totals+audit; restore+verify; etc.).

## 3. Data locations (Windows)

- Database: `%APPDATA%/DentivaPro/dentiva.db` (per-user app data; never Program Files).
- Attachments: `%APPDATA%/DentivaPro/attachments/<patientId>/<uuid>_<safe>`.
- Backups: user-selected folder (default `%APPDATA%/DentivaPro/backups`).
- Logs: `%APPDATA%/DentivaPro/logs/` (no secrets, no passwords, minimal PHI).

## 4. Modules

patients, visits, dental-chart, treatments, prescriptions, appointments, queue,
invoices, payments, inventory, accounting, staff/users/RBAC, notifications,
audit, backup/restore, settings (clinic, dentists, users, roles, printing,
templates, categories, suppliers), reports, global search, dashboard.

## 5. Cross-cutting concerns

- **Auth/session:** Argon2id password hashes; in-memory session + lock state;
  auto-lock timer (5/10/15/30 min, or Never with owner policy).
- **Activation:** one-time code verified against a one-way derived verifier
  (SHA-256 domain-separated digest; no plaintext in source), persisted + device-bound.
- **Audit:** every mutating command writes `audit_logs`; audit is append-only for
  non-owners.
- **Notifications:** generated by business events (appointments, stock, backup…).
- **Print engine:** `src/print/engine.ts` — document-type + data + printer profile
  + paper → paginated HTML; preview with real paper dimensions; output via OS
  print (covers standard/wireless/BT Windows printers + Save-as-PDF).
- **i18n/input:** UI in English; all free-text fields accept Bengali Unicode;
  Noto Sans Bengali bundled for UI/print/PDF fidelity.

## 6. Build & release

- `vite build` → `src-tauri/target/release` via `tauri build` (NSIS `.exe`).
- GitHub Actions: `ci.yml` (lint/typecheck/unit/integration/audits) and
  `release.yml` (Windows build → `.exe` → GitHub Release; `/dist` fallback).
- Version single-sourced: `package.json` + `src-tauri/tauri.conf.json` + About screen.
